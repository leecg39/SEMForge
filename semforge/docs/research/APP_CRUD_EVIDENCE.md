# Semrush 로그인 앱 — CRUD 화면 증거 기록

> 관찰 일시: 2026-07-28 (Asia/Seoul)
> 관찰 도구: ego-lite 브라우저(사용자 로그인 세션 상속), 뷰포트 1420×850 / 375×812
> 관찰 계정: 무료 플랜(활성 구독 없음), 로케일 `ko.semrush.com`, 초기 폴더 1개
> 쓰기 작업 범위: `ZZ_TEST_` 접두사 데이터만 생성 후 전량 삭제. 원본 계정 데이터(`My Folder`)는 변경하지 않음.

## 증거 등급 정의

| 등급 | 의미 |
|---|---|
| `O` | 이 세션에서 직접 관찰됨 |
| `I1` | 여러 화면·동작에서 강하게 추론됨 |
| `I2` | 일반적인 UX 관행에 근거한 약한 가정 |

| `P` | 새 시스템을 위한 제안 |

## 1. 관찰 환경의 제약 (매우 중요)

| 사실 | 등급 | 영향 |
|---|---|---|
| 계정에 활성 구독이 없어 Position Tracking / Keyword Strategy Builder / Media Lists / My Reports / Content / Site Audit 이 모두 **작업공간 대신 마케팅 랜딩**을 표시 | `O` | 이 6개 도메인의 목록·상세·필터·일괄작업 화면을 **직접 관찰하지 못함** (`U`) |
| `사용자 초대` 버튼을 클릭해도 아무 반응이 없음(오버레이/인라인 폼 미출현, body 텍스트 길이 불변 525→525) | `O` | 역할 목록과 권한별 차이를 **확인하지 못함** (`U`) |
| 계정에 데이터가 없을 때는 목록 화면 자체가 렌더되지 않고 온보딩 랜딩으로 대체됨 | `O` | "빈 상태"의 실제 구현이 별도 화면 전환임을 확인 |
| 폴더를 1개 생성하자 즉시 필터·보기전환·KPI가 포함된 **완전한 목록 UI**가 나타남 | `O` | 목록 UI는 데이터 존재 여부에 따라 조건부 렌더 |

따라서 아래 3절(폴더/프로젝트)은 `O` 중심이고, 6개 툴킷 도메인은 진입점·랜딩 문구만 `O`이며 내부 CRUD는 `U`/`P`로 표기한다.

## 3. 폴더(Folder) 도메인 — 인터랙션 스윕 결과

### 3.1 Create (`O`)

- 진입점: 홈 `폴더 만들기` 버튼(우측 상단)
- 다이얼로그 필드
  | 라벨 | 컨트롤 | placeholder | HTML required | 비고 |
  |---|---|---|---|---|
  | 웹사이트 | text | `도메인 또는 서브도메인 입력` | 없음 | 힌트 "웹사이트가 없다면 경쟁자를 추가하세요", 별도 `웹사이트 필드 정보` 툴팁 존재 |
  | 비즈니스명 | text | `비즈니스 이름 입력` | 없음 | 폴더 표시명으로 사용됨 |
  | 보고서가 생성되면 공유하기 | checkbox | — | — | 기본 해제 |
- 버튼: `생성` / `취소` / `닫기`
- **검증 관찰**
  - 빈 값으로 `생성` → `aria-invalid=true` 요소 2개 발생, 다이얼로그 유지, URL 불변, 데이터 생성 안 됨 → 두 필드 모두 필수 (`O`)
  - `htp:/// not a domain !!!` + 비즈니스명 입력 후 `생성` → 인라인 메시지 **"올바른 웹사이트를 입력하세요."**, `aria-invalid` 1개 → 도메인 형식 검증 존재 (`O`)
  - HTML `required` 속성은 없음 → 검증은 스크립트 레벨 (`O`)
- **성공 결과** (`O`)
  - 다이얼로그 닫힘, 성공 토스트 **없음**
  - 폴더 목록 즉시 갱신, 새 폴더에 `fid=12800840` 발급
  - 상단에 툴킷 프로모 카드 캐러셀이 새로 노출됨(폴더 존재 시 조건부 렌더)
  - 생성 직후 AI 가시성 지표가 값과 함께 표시됨(`17` 언급, `1.7천`) → 생성 시 백그라운드 분석이 자동 트리거됨 (`I1`)

### 3.2 Read — 목록 (`O`)

- 섹션 헤더: `폴더` + `필터 숨기기 및 보기 전환` 토글 링크 + 우측 `공유` / `+ 폴더 만들기`
- 필터 행
  - 검색 입력 placeholder **`웹사이트 또는 폴더 이름`** → 검색 대상 필드 2개 (`O`)
  - `소유권` 드롭다운 옵션: **`내 소유`**, **`나에게 공유된 캠페인`** (`O`)
  - `태그` 드롭다운 (태그가 없어 옵션 목록 미확인, `U`)
  - `테이블 보기(SEO 전용)` 스위치
- 카드 보기 행 구성 (`O`)
  - 아이콘 + 폴더명(링크, `#235FE2`, 16px/700) + 도메인 + 외부링크 아이콘 + 우측 kebab
  - 도메인이 없는 폴더: `+ 웹사이트 추가` 버튼과 빈 상태 문구 "웹사이트를 추가하여 순위, 키워드 백링크를 모니터링하고, 문제를 해결하고, LLM 전반에서의 가시성을 높여보세요."
  - 도메인이 있는 폴더: `SEO` / `AI 가시성`(게이지) / `언급` / `Site Health` / `가시성` / `자연검색 트래픽` / `자연 키워드` / `백링크`
  - 미설정 지표는 `n/a` 또는 설명문 + `설정` 링크
  - 각 지표는 해당 분석 화면으로 딥링크 (`/analytics/overview/?q=<domain>&searchType=subdomain` 등)
- 테이블 보기 컬럼 (`O`): `폴더` / `Site Health` / `가시성` / `유해한 도메인` / `실행할 아이디어` / `백링크 잠재 도메인` / `자연 세션`, 접근성 텍스트 `정렬 가능`
- 로딩 상태 (`O`): 테이블 보기 전환 시 **"데이터 로드 중"** 텍스트 노출
- 하단 `모니터링할 도메인` 아코디언(`Open` 토글) (`O`)
- 실제 `<table>` 요소는 사용하지 않음(div 기반 그리드) (`O`)

### 3.3 Update (`O`)

- 진입점 2개: kebab → `설정`, 또는 삭제 확인 전 단계의 설정 다이얼로그
- 다이얼로그 제목 `폴더 설정`
- **수정 가능 필드**: 비즈니스명(현재값 프리필)
- **수정 불가 필드**: 도메인이 이미 설정된 폴더는 `웹사이트: zz-test.example.com` 형태의 **읽기 전용 텍스트**로 표시됨. 도메인이 없는 폴더에서는 같은 자리가 `(선택사항)` 라벨의 입력 필드였음 → **도메인은 1회 설정 후 불변** (`O`)
- 체크박스: `저장 후 공유하기`
- 버튼: `저장` / `취소` / `폴더 삭제`(다이얼로그 하단에 파괴적 액션 배치)
- 결과: 저장 시 다이얼로그 닫힘, 목록 즉시 갱신(`ZZ_TEST_폴더` → `ZZ_TEST_폴더_수정됨`), **성공 토스트 없음** (`O`)
- 자동 저장 아님(명시적 저장 버튼) (`O`)
- 이탈 경고·변경 이력·동시 수정 충돌 처리는 관찰되지 않음 (`U`)

### 3.4 Delete (`O`) — 가장 중요한 발견

- 진입점 2개: kebab → `삭제`, 설정 다이얼로그 → `폴더 삭제`
- 확인 다이얼로그 전문 (실측)
  ```
  폴더 삭제
  비즈니스명: ZZ_TEST_폴더_수정됨
  이 폴더 및 연결된 모든 데이터가 삭제됩니다

  다음 도구에 연결된 데이터가 없는지 확인하세요.
  • SEO 프로젝트
  • 트래픽 & 시장
  • 소셜
  • 콘텐츠
  • 광고
  삭제를 계속 진행하려면 이 코드 입력: 916116
  [삭제] [취소]
  ```
- **2차 확인 = 랜덤 6자리 코드 입력** (`O`). 호출마다 코드가 다름(1회차 `661288`, 2회차 `916116`) → 서버/클라이언트가 매 요청마다 새 코드 생성 (`I1`)
- 코드 입력 후 `삭제` 버튼 활성(`disabled: false`) (`O`)
- **삭제 후 결과** (`O`)
  - 목록에서 즉시 제거
  - 토스트/스낵바 **없음**
  - `되돌리기`/`실행 취소`/`Undo`/`복구` 문자열 **없음**
  - `휴지통`/`Trash`/`삭제된` 문자열 **없음**
- 관계 데이터 처리: UI가 삭제를 막지 않고 **경고 후 사용자 판단에 맡김**. "연결된 모든 데이터가 삭제됩니다"라는 문구는 CASCADE 삭제를 시사 (`I1`)
- 소프트 삭제 여부: 휴지통·복구 UI가 어디에도 없고 문구도 영구 삭제를 시사 → **하드 삭제(또는 사용자에게 노출되지 않는 내부 보존)** (`I1`). 서버 내부 실제 저장 방식은 확인 불가 (`U`)

## 4. 계정·사용자 도메인 (실측)

### 4.1 프로필 설정 (`O`)

- 탭: `개인 정보` / `이메일` / `비밀번호` / `보안`
- 읽기 전용 표시: 이메일, `ID`, `회원가입 날짜`
- 수정 가능: `성명`(name), `전화번호`(phone), `회사`(company), `국가`(드롭다운), `시간대`(드롭다운)
- 버튼: `변경사항 저장하기` / `취소` → 명시적 저장 (`O`)

### 4.2 사용자 관리 (`O` 부분)

- 버튼 `사용자 초대` 존재하나 무료 플랜에서 클릭 무반응 (`O`) → 플랜 게이트 (`I1`)
- 빈 상태 설명에서 도출되는 권한 개념 (`I1`)
  - "팀원별로 고유한 로그인 정보" → 사용자별 계정
  - "프로젝트를 공유하고 다른 사람들과 협업" → 리소스 공유
  - "프로젝트, 사용 현황, 쿼리 기록을 조회하여 사람들이 무엇을 하고 있는지 모니터링" → 관리자용 감사 조회
  - "**관리자에게 사용자 관리 작업을 할당**" → 최소 2단계 역할(소유자 / 관리자)이 존재 (`I1`)
- 구체적 역할 이름·권한 매트릭스 (`U`)

### 4.3 알림 설정 (`O`)

- 그룹 `일반` 아코디언에 `3/3 활성` 카운터 표시
- 체크박스 3개: `교육 콘텐츠`, `제품 소식 및 업데이트`, `예정된 이벤트` (모두 기본 on)
- 저장 버튼 없음 → 토글 즉시 반영(자동 저장) (`I1`)

### 4.4 활동 로그 (`O`)

- 컬럼: `날짜 및 시간` / `이벤트 유형` / `IP` / `국가` / `사용자 에이전트` + `정렬 가능`
- 관찰된 `이벤트 유형` 값: `login`, `registration`
- 페이지네이션: `?page=1`, 하단에 `페이지: [입력] / 1` 형태의 숫자 입력형
- **폴더 생성·수정·삭제를 수행한 뒤에도 새 항목이 추가되지 않음** (`O`)
  → Semrush 활동 로그는 **인증/계정 보안 이벤트 전용**이며 엔티티 CRUD 감사 로그가 아니다 (`O`, 관찰 범위 내 확정)

### 4.5 쿼리 로그 (`O`)

- 탭: `웹 쿼리` / `API 쿼리`
- 시간대 고정 표기: `(UTC+00:00) GMT`
- `마지막으로 결과를 다운로드한 날짜: 7월 27, 2026 08:18 오후` → 내보내기 이력 표시
- 빈 상태: "아직 쿼리가 없습니다. Semrush에서 검색하신 도메인, URL 및 키워드와 관련된 모든 쿼리 내역이 표시됩니다." + `대시보드로 이동`
- 부분 실패/제한 상태 문구: **"쿼리가 너무 많습니다. 잠시만 기다려 주시거나 오늘의 데이터만 불러오세요."** + `오늘의 데이터 불러오기` (`O`)
- `전송` 버튼 존재(이메일 전송 추정, `I2`)

### 4.6 API Keys (`O`)

- 탭 = 상태 필터: `Active` / `Inactive` (경로 세그먼트 `/active`)
- 컬럼: `Key` / `Permissions` / `Version` / `Created` / `Expires` + `정렬 가능`
- 빈 상태: `Nothing here yet` / `Create an API key to start.`
- 버튼: `Create API key`
- **Active/Inactive 분리는 삭제 대신 비활성 전이(=소프트 삭제 계열) 패턴** (`I1`)
  → 동일 제품 안에서도 엔티티별 삭제 정책이 다르다: 폴더는 영구 삭제형, API 키는 상태 전이형 (`I1`)

## 9. 숨은 업무 규칙 추론

각 항목은 `관찰된 증거 → 추론한 규칙 → 신뢰도 → 다른 해석 → 권장 기본값 → 추가 확인 방법` 순서로 기록한다.

### R1. 폴더의 도메인은 1회 설정 후 불변

- **관찰**: 도메인이 없는 `My Folder`의 설정 다이얼로그에는 `웹사이트 (선택사항)` 입력 필드가 있었으나, 도메인이 있는 `ZZ_TEST_폴더`에서는 `웹사이트: zz-test.example.com` 읽기 전용 텍스트로 렌더됨.
- **추론**: 도메인은 폴더의 식별 축이며 설정 후 변경 불가.
- **신뢰도**: 높음 (`I1`)
- **다른 해석**: 변경은 가능하나 별도 화면(웹사이트 관리)에서만 허용될 수 있음.
- **권장 기본값**: 생성 시 1회 설정, 이후 불변. 변경이 필요하면 폴더를 새로 만들도록 유도.
- **추가 확인**: 유료 플랜에서 웹사이트 여러 개를 연결한 뒤 설정 화면 재확인.

### R2. 폴더 이름(비즈니스명)은 필수, 도메인은 생성 시 필수·수정 시 선택

- **관찰**: 빈 값 제출 시 `aria-invalid` 2개(두 필드 모두). 수정 화면 라벨은 `(선택사항)`.
- **추론**: 생성 폼과 수정 폼의 필수 규칙이 다르다.
- **신뢰도**: 중간 (`I1`)
- **다른 해석**: `aria-invalid` 2개 중 하나가 체크박스 래퍼일 가능성.
- **권장 기본값**: 이름 필수(1~100자), 도메인은 생성 시 필수로 두되 "경쟁사 도메인이라도 입력" 힌트를 함께 제공.
- **추가 확인**: 도메인만 비우고 이름만 채워 제출.

### R3. 삭제는 영구 삭제이며 사용자에게 복구 경로를 제공하지 않는다

- **관찰**: 확인 문구 "이 폴더 및 연결된 모든 데이터가 삭제됩니다", 랜덤 코드 2차 확인, 삭제 후 undo/휴지통/복구 문자열 전무.
- **추론**: 폴더는 하드 삭제 + 관계 데이터 CASCADE.
- **신뢰도**: 높음 (`I1`) / 서버 내부 보존 여부는 `U`
- **다른 해석**: 서버는 소프트 삭제하지만 UI에 노출하지 않을 수 있음(GDPR 대응 지연 삭제).
- **권장 기본값**: **재구축에서는 소프트 삭제 + 휴지통 + 관리자 전용 영구 삭제로 변경**(프롬프트 정책). 원본과 다른 점으로 명시.
- **추가 확인**: 삭제 직후 동일 도메인으로 재생성해 지표 이력이 살아나는지 확인.

### R4. 파괴적 작업은 "이름 확인"이 아니라 "랜덤 코드 입력"으로 게이팅한다

- **관찰**: 매 호출마다 새로운 6자리 숫자(`661288`, `916116`)를 표시하고 입력을 요구.
- **추론**: 복사-붙여넣기 습관화를 막고 실수 삭제를 방지하는 의도적 마찰.
- **신뢰도**: 높음 (`I1`)
- **다른 해석**: 봇/자동화 방지 목적.
- **권장 기본값**: 영구 삭제에만 코드 입력을 적용하고, 소프트 삭제(휴지통 이동)는 단순 확인으로 둔다.
- **추가 확인**: 코드를 틀리게 입력했을 때의 오류 문구 확인.

### R5. 소유권은 "내 소유"와 "공유받음"의 2분류이며 공유는 캠페인 단위

- **관찰**: 소유권 필터 옵션이 정확히 `내 소유` / `나에게 공유된 캠페인`. `owning=all` 쿼리 파라미터.
- **추론**: 리소스마다 소유자(생성자)가 있고, 공유 대상자는 읽기 위주 접근을 받는다. 옵션 문구가 "폴더"가 아니라 "캠페인"인 점에서 공유 단위는 폴더 하위 캠페인.
- **신뢰도**: 중간 (`I1`)
- **다른 해석**: 문구가 레거시이고 실제 공유 단위는 폴더일 수 있음.
- **권장 기본값**: 폴더·캠페인 모두에 `createdBy` 소유자와 공유 목록을 두고, 필터는 `all|my|shared`.
- **추가 확인**: 두 번째 사용자를 초대해 공유 후 필터 결과 비교.

### R6. 활동 로그는 인증 이벤트 전용이고 엔티티 감사 로그는 사용자에게 노출되지 않는다

- **관찰**: 폴더 3회 변경(생성/수정/삭제) 후에도 활동 로그는 `login`, `registration` 2건 그대로. 컬럼도 IP/국가/UA 중심.
- **추론**: 활동 로그의 목적은 계정 보안(무단 로그인 감지)이며 데이터 변경 추적이 아니다.
- **신뢰도**: 높음 (`O` 범위 내 확정)
- **다른 해석**: 엔티티 감사 로그가 존재하지만 유료 플랜/관리자에게만 노출될 수 있음(사용자 관리 설명의 "무엇을 하고 있는지 모니터링" 문구가 이를 시사).
- **권장 기본값**: 재구축에서는 인증 로그와 엔티티 감사 로그를 **분리된 두 화면**으로 제공하고, 엔티티 감사 로그는 관리자 전용.
- **추가 확인**: 팀 계정에서 관리자 계정으로 로그인해 추가 로그 화면 존재 확인.

### R7. 엔티티마다 삭제 정책이 다르다

- **관찰**: 폴더 = 코드 확인 후 영구 삭제 / API 키 = `Active`·`Inactive` 탭으로 상태 분리.
- **추론**: 되돌릴 수 없는 자산(폴더+연결 데이터)은 하드 삭제, 자격증명은 폐기 후 이력 보존.
- **신뢰도**: 중간 (`I1`)
- **다른 해석**: API 키의 Inactive 는 만료 상태이고 삭제는 별도로 존재.
- **권장 기본값**: 자격증명·로그성 엔티티는 상태 전이, 사용자 생성 콘텐츠는 소프트 삭제.
- **추가 확인**: API 키를 만들고 삭제해 어느 탭으로 이동하는지 확인.

### R8. 성공 알림을 토스트로 주지 않고 목록 갱신으로 대체한다

- **관찰**: 생성·수정·삭제 3회 모두 `[role=status]`/`[role=alert]`/toast 클래스 요소가 0건.
- **추론**: 낙관적 UI 갱신을 성공 피드백으로 사용.
- **신뢰도**: 중간 (`I1`) — 토스트가 짧게 떴다가 6초 대기 중 사라졌을 가능성 있음.
- **다른 해석**: 관찰 타이밍 문제.
- **권장 기본값**: 재구축에서는 접근성을 위해 `aria-live` 상태 메시지를 추가(원본과 다른 점으로 명시).
- **추가 확인**: 저장 직후 0.5초 간격으로 DOM 스냅샷 연속 촬영.

### R9. 존재하지 않는 리소스 ID는 404가 아니라 상위 랜딩으로 폴백한다

- **관찰**: `/seo/?fid=999999999` → 오류 없이 SEO 툴킷 마케팅 랜딩 렌더.
- **추론**: 리소스 존재 여부를 노출하지 않는 설계(열거 공격 방어) 또는 단순히 잘못된 파라미터 무시.
- **신뢰도**: 중간 (`I1`)
- **다른 해석**: 폴더 컨텍스트 로딩 실패 시 기본 화면으로 되돌리는 일반 폴백.
- **권장 기본값**: 재구축에서는 타 테넌트 리소스와 존재하지 않는 리소스를 **모두 404로 동일 처리**(존재 여부 비노출)하되, 앱 내에서는 "찾을 수 없음" 화면을 명시적으로 보여준다.
- **추가 확인**: 로그인 상태에서 타 사용자 폴더 ID 접근은 **시도하지 않음**(권한 우회 금지 원칙).

### R10. 플랜이 기능 게이트의 1차 축이다

- **관찰**: 6개 툴킷이 모두 랜딩/트라이얼 CTA, `사용자 초대` 무반응, 폴더 CRUD는 무료에서도 가능.
- **추론**: 폴더/프로젝트 골격은 무료 허용, 데이터 집약 도구와 팀 협업은 유료.
- **신뢰도**: 높음 (`I1`)
- **다른 해석**: A/B 테스트 또는 신규 계정 온보딩 단계.
- **권장 기본값**: `plan` 필드로 기능 게이트를 구현하고, 게이트는 **서버에서도** 검사.
- **추가 확인**: 트라이얼 시작 후 동일 화면 재관찰.
