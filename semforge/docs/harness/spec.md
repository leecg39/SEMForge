# `/siteaudit/` 프로젝트 목록 및 진단 실행 UX 개편 사양

## 1. 목적

SEO 사이드 내비게이션의 `사이트 진단`을 눌렀을 때, 바로 단일 캠페인의 상세 리포트를 노출하지 않고 첨부 영상처럼 워크스페이스의 SEO 프로젝트별 진단 상태를 한눈에 비교하는 목록 화면을 제공한다. 사용자는 이 화면에서 프로젝트 생성, Site Audit 설정, 실행 진행 확인, 완료 결과 비교, 상세 리포트 진입까지 끊김 없이 수행할 수 있어야 한다.

구현은 현재 SEMForge의 Next.js 16 + React 19 + Drizzle/SQLite 구조와 실제 Firecrawl·PageSpeed Insights 데이터 연동 원칙을 유지한다. 측정하지 못한 값은 `0`으로 꾸미지 않고 `—` 또는 `수집 전`으로 표시한다.

## 2. 영상에서 확인한 UX 근거

첨부 영상은 2032×1162, 약 106초, 무음 화면 녹화이며 핵심 장면은 다음과 같다.

| 시점 | 관찰된 화면/동작 | 반영할 요구사항 |
|---|---|---|
| 0초 | `사이트 진단` 제목, 검색창, `SEO 프로젝트 만들기`, 프로젝트별 13개 지표 열 | `/siteaudit/`의 기본 화면을 프로젝트 비교 목록으로 구성 |
| 6~18초 | 도메인과 선택적 이름을 입력하는 프로젝트 생성 모달, 존재하지 않는 도메인 경고 | 도메인 정규화·형식/도달 가능성 검증·필드별 오류 제공 |
| 32~40초 | 정상 도메인 입력, 기존 동일 도메인 프로젝트 안내 | 중복은 정보성 경고로 알리되 사용자가 명시적으로 계속할 수 있게 함 |
| 48~60초 | 좌측 단계 내비게이션이 있는 `새 진단` 모달, 범위·페이지 한도·수집 소스·스케줄·알림 설정 | 프로젝트 생성과 진단 설정을 분리하고, 기존 프로젝트도 `설정` 가능하게 함 |
| 64초 | `크롤링 준비 중…` 로딩 상태 | 설정 저장과 실행 큐 등록 사이의 명확한 중간 상태 제공 |
| 72초 | 청록색 실행 중 행, 각 지표 스피너, 안내 문구 | 실행 중인 프로젝트를 목록 안에서 눈에 띄게 표시 |
| 105초 | `1/100`처럼 실제 크롤 진행 수치 노출 | 새로고침/재방문 후에도 유지되는 서버 저장형 진행률 구현 |

## 3. 현재 구현과의 차이

현재 `/siteaudit/`는 `SiteAuditDashboard` 하나에서 프로젝트 선택, 상세 탭, 실행 배너, 프로젝트 표를 모두 렌더링한다. 진단 실행 API는 요청이 끝날 때까지 크롤을 동기적으로 기다리고, 페이지·이슈 데이터는 최신 1회 결과로 교체한다.

따라서 다음 차이를 해소해야 한다.

- 기본 진입 화면과 상세 리포트를 분리한다.
- `folders`를 SEO 프로젝트의 원본으로 사용하고, Site Audit이 아직 설정되지 않은 프로젝트도 목록에 표시한다.
- 실행 이력과 진행률을 별도 저장해 새로고침 후에도 상태를 복원한다.
- 최신 결과만 보여주는 현재 구조에 실행 스냅샷을 추가해 이전 실행 대비 증감을 실제 데이터로 계산한다.
- Core Web Vitals와 사이트 성능 값은 PageSpeed Insights 응답이 있을 때만 표시한다.

## 4. 목표 사용자 흐름

1. 사용자가 SEO 사이드 내비게이션에서 `사이트 진단`을 누른다.
2. `/siteaudit/`는 프로젝트 현황 목록을 표시한다.
3. 기존 프로젝트는 상태에 따라 완료 지표, `설정`, 실행 중 진행률, 실패/재시도 상태 중 하나를 보여준다.
4. `SEO 프로젝트 만들기`를 누르면 도메인과 선택적 프로젝트 이름을 입력한다.
5. 서버가 도메인을 정규화하고 안전하게 도달 가능성을 검사한다. 이름을 비워두면 도메인에서 자동 생성한다.
6. 프로젝트 생성 후 같은 흐름에서 `새 진단` 설정 모달을 연다.
7. 일반 설정을 저장하고 `진단 시작`을 누르면 실행을 큐에 넣고 즉시 목록으로 돌아온다.
8. 목록 행은 실행 중 상태로 전환되고 실제 수집 페이지 수를 주기적으로 갱신한다.
9. 완료되면 최신 값과 이전 완료 실행 대비 증감을 표시한다.
10. 프로젝트명을 누르면 기존 상세 리포트 화면(`/siteaudit/?campaign=<id>`)으로 이동한다.

## 5. 화면 구성

### 5.1 공통 셸

- 기존 `AppShell`, 전역 아이콘 레일, `ToolkitSideNav`를 그대로 사용한다.
- 1904×947 뷰포트에서는 콘텐츠 영역을 최대한 넓게 사용하고, 헤더 아래에 `홈페이지 > SEO > 사이트 진단` 브레드크럼과 24px 제목을 둔다.
- 사이드 내비게이션의 `사이트 진단`은 `/siteaudit/` 목록으로 항상 돌아오는 진입점이다.

### 5.2 프로젝트 현황 카드

- 상단 툴바: 좌측 300px 검색창, 우측 `+ SEO 프로젝트 만들기` 버튼.
- 표 헤더: 프로젝트, 마지막 업데이트, 크롤링된 페이지, Site Health, AI 검색 상태, 오류, 경고, 크롤링 가능성, HTTPS, 인터내셔널 SEO, 사이트 성능, 내부 링크, 마크업, Core Web Vitals.
- 프로젝트 셀: 프로젝트명 링크, 도메인, 설정 아이콘. 첫 열은 가로 스크롤 시 고정한다.
- 지표 셀: 현재 값 1행, 이전 완료 실행 대비 증감 2행. 비교 데이터가 없으면 `—`.
- 하단: 페이지 번호, 전체 페이지 수, 페이지 크기 10/25/50.

### 5.3 행 상태

- `설정 전`: 프로젝트와 도메인만 표시하고 `설정` 버튼을 제공한다.
- `큐 대기/준비 중`: 청록색 배경, 준비 메시지, 지표 스켈레톤.
- `실행 중`: 청록색 배경, 실제 `수집 수/제한 수`, 각 지표 스피너, 재방문 가능 안내.
- `완료`: 실측 지표와 증감, 마지막 완료 시각, 상세 링크.
- `실패`: 옅은 적색 배경, 사용자용 실패 사유, `다시 시도`와 `설정 열기`.
- `수집 불가`: 값 대신 `—`, 제공사/도메인 오류를 툴팁 또는 상태 문구로 설명한다.

### 5.4 SEO 프로젝트 생성 모달

- 필드: 도메인(필수), 이름(선택).
- 도메인은 스킴과 경로를 제거해 호스트로 정규화하고, 하위 경로 입력은 지원하지 않는다고 안내한다.
- 형식 검증 후 서버에서 공인 호스트인지와 HTTP(S) 도달 가능성을 검사한다. 내부 IP·로컬 주소는 SSRF 방지를 위해 차단한다.
- 동일 도메인 프로젝트가 있으면 기존 프로젝트 링크와 함께 정보성 경고를 표시한다.
- 생성 성공 시 `folders`에 SEO 프로젝트를 만들고 바로 해당 프로젝트의 진단 설정으로 이어간다.

### 5.5 새 진단 설정 모달

- 좌측 어두운 단계 내비게이션, 우측 설정 폼의 2열 구조로 구성한다.
- P0 일반 설정: 범위(도메인/정확한 서브도메인), 진단당 페이지 한도, 크롤링 소스(웹사이트/사이트맵), 일정, 완료 알림.
- P1 고급 설정: 크롤러 선택, 허용/비허용 규칙, URL 매개변수 규칙.
- 고급 설정은 백엔드가 실제로 적용할 수 있는 단계부터 활성화하며, 표시만 되는 가짜 컨트롤은 만들지 않는다.
- 저장 중에는 중복 제출을 막고, 큐 등록 후 모달 안에서 `크롤링 준비 중…` 상태를 잠시 보여준 뒤 목록으로 복귀한다.

### 5.6 상세 리포트

- 기존 `SiteAuditDashboard`의 개요/문제/크롤링된 페이지/통계/테마 보고서를 유지한다.
- 프로젝트 목록에서는 프로젝트명을 눌러 `?campaign=`으로 진입한다.
- 상세 상단에 `사이트 진단 목록으로 돌아가기`와 현재 프로젝트 컨텍스트를 명확히 표시한다.

## 6. 기능 및 데이터 설계

### 6.1 프로젝트와 캠페인 관계

- `folders`를 SEO 프로젝트로 간주한다.
- `site_audit_campaigns.folder_id`로 프로젝트와 설정을 연결한다.
- 한 활성 SEO 프로젝트당 하나의 활성 Site Audit 캠페인을 원칙으로 하고 DB 제약과 서버 검증으로 중복 설정을 막는다.
- 기존 `folder_id`가 없는 캠페인은 마이그레이션 또는 호환 조회 규칙으로 목록에서 유실되지 않게 한다.

### 6.2 실행 이력과 진행률

- 실행 단위 `SiteAuditRun`을 추가해 queued/running/completed/failed 상태, 한도, 현재 수집 수, 시작/완료 시각, 엔진, 오류, 지표 스냅샷, 데이터 출처를 저장한다.
- 실행 요청은 먼저 run 행을 만든 뒤 즉시 202 응답하고, Next.js `after()`에서 실제 크롤을 시작한다.
- 프로세스 중단에 대비해 기존 due-runner가 남은 queued 실행과 오래된 running 실행을 회수할 수 있게 한다.
- Firecrawl 및 자체 크롤러에 진행 콜백을 추가하고 일정 페이지 단위로 run 진행률을 갱신한다.
- 동일 캠페인의 동시 실행은 DB 상태 전이로 원자적으로 차단한다.

### 6.3 목록 지표

- 크롤링된 페이지, Site Health, 오류/경고: 현재 크롤 분석 결과.
- 크롤링 가능성, HTTPS, 내부 링크, 마크업, AI 검색 상태: 기존 `getSiteAuditOverview` 테마 계산 결과.
- 사이트 성능과 Core Web Vitals: PageSpeed Insights 실측 결과가 있을 때 실행 스냅샷에 저장.
- 인터내셔널 SEO: 실제 hreflang 등 측정 로직을 추가하기 전까지 `—`로 표시.
- 증감: 최신 완료 실행과 직전 완료 실행의 동일 지표 차이. 첫 실행이거나 비교 불가능하면 `—`.
- 모든 값에 `firecrawl`, `built-in crawler`, `pagespeed-insights` 등 provenance를 보존한다.

### 6.4 목록 조회

- 서버에서 워크스페이스의 `folders`와 활성 Site Audit 캠페인, 최신/직전 run을 조합한다.
- 검색은 프로젝트명과 도메인을 대상으로 하며 서버 페이지네이션을 사용한다.
- 기본 정렬은 마지막 업데이트 내림차순, 이름 오름차순을 지원한다.
- 실행 중에는 2~3초 폴링하고, 실행 중인 행이 없으면 폴링을 중단한다.

## 7. 구현 단계

### Phase 1 — 목록 정보 구조와 프로젝트 연결 (P0)

- `/siteaudit/`를 목록 모드와 상세 모드로 분기한다.
- 폴더 + 캠페인 조합 조회와 목록용 응답 모델을 만든다.
- 영상 기반 표, 검색, 정렬, 페이지네이션, 상태별 행을 구현한다.
- 기존 캠페인/상세 리포트 링크의 호환성을 유지한다.

### Phase 2 — 생성 및 설정 흐름 (P0)

- SEO 프로젝트 생성 모달과 안전한 도메인 검증을 구현한다.
- 현재 `SiteAuditSetupDialog`를 프로젝트 기반 단계형 설정 모달로 개편한다.
- 설정 전 프로젝트, 생성 직후 설정 이어가기, 취소 후 재설정 흐름을 완성한다.

### Phase 3 — 비동기 실행과 진행률 (P0)

- 실행 이력 마이그레이션과 상태 전이 로직을 추가한다.
- 크롤러 진행 콜백, 백그라운드 실행, 폴링, 중단 복구를 구현한다.
- 영상의 청록색 진행 행과 `n/limit` 표시를 실제 데이터로 연결한다.

### Phase 4 — 지표 스냅샷과 변화량 (P0/P1)

- 완료 시 테마·이슈·PSI 결과를 스냅샷으로 저장한다.
- 최신/직전 실행 비교와 미측정 상태를 목록에 표시한다.
- 상세 리포트는 최신 완료 실행을 읽도록 기존 동작을 보존한다.

### Phase 5 — 고급 설정, 알림, 접근성/반응형 (P1/P2)

- 백엔드 적용이 가능한 고급 크롤 규칙부터 단계적으로 활성화한다.
- 완료 알림을 인앱 알림과 구성된 메일 채널에 연결한다.
- 1024px 이하에서는 지표 표를 가로 스크롤 또는 요약 카드로 전환한다.
- 키보드 포커스, 모달 포커스 트랩, 상태 live region, 색상 외 상태 표기를 검증한다.

## 8. 예상 변경 영역

- `src/app/(app)/siteaudit/page.tsx`: 목록/상세 서버 분기와 초기 데이터 로딩.
- `src/components/siteaudit/`: 프로젝트 목록, 생성 모달, 설정 모달, 상태 행, 지표 셀로 컴포넌트 분리.
- `src/server/siteaudit/`: 목록 집계, 실행 큐/이력, 진행률, 스냅샷, 변화량 계산.
- `src/app/api/site-audits/`: 목록 상태 조회, 설정, 실행 시작/상태 조회 계약 확장.
- `src/db/schema/domain.ts` 및 신규 마이그레이션: 실행 이력, 완료 알림, 프로젝트-캠페인 제약.
- `src/server/siteaudit/*.test.ts`: 상태 전이, 지표 계산, 변화량, 테넌트 격리 테스트.

## 9. 완료 기준

- 1904×947에서 영상과 같은 우선순위로 제목, 툴바, 전체 지표 표가 배치된다.
- 사이드 내비게이션의 `사이트 진단` 클릭은 항상 프로젝트 목록을 연다.
- 설정되지 않은 프로젝트가 목록에서 사라지지 않고 `설정` 동작을 제공한다.
- 도메인 오류·중복 안내가 필드 수준에서 이해 가능하게 표시된다.
- `진단 시작` 후 2초 내 목록이 실행 상태로 바뀌며 새로고침해도 진행 상태가 유지된다.
- 수집 진행률은 실제 처리 페이지 수를 반영하고 완료 시 결과 지표로 교체된다.
- 첫 실행의 변화량과 미측정 지표를 가짜 `0%`로 표시하지 않는다.
- 프로젝트명을 누르면 기존 상세 리포트가 정상 동작한다.
- 다른 워크스페이스의 프로젝트·실행 이력은 조회하거나 실행할 수 없다.
- Firecrawl/PSI 실패 시 오류 상태와 재시도 경로가 제공되며 하드코딩 데이터로 대체하지 않는다.
